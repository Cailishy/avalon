# 安全边界

这份说明面向部署者和贡献者，描述代码依赖哪些边界，不记录真实环境、凭证、内部审计过程或未公开漏洞。报告问题请看根目录 [安全政策](../../SECURITY.md)。

## 游戏服务

- 房间、阶段、计时、投票和胜负以服务器为准。事件入口校验负载，领域层再校验玩家会话、身份和操作权限。
- 普通对局只向本人发送私密身份信息；公开头像与角色分离，任务牌只公开汇总。刺杀与结算按规则公开相应身份。
- 请求包含意图编号和阶段编号，重试不应重复执行；回执有容量与时效边界，不承诺跨数据库丢失后的无限期去重。
- 入场暗号和玩家会话分开。共享暗号不是账号、实名、封禁或防合谋系统，泄漏后需要轮换。

## 公网部署

生产模式接入可信 HTTPS / WSS，Caddy 只代理固定游戏上游。Node 原始端口不直接暴露公网；可信代理必须限定到实际代理地址，不能信任任意转发头。

HTTP、连接、消息和房间使用独立资源预算。应用限流不能防住带宽洪泛、分布式攻击或宿主机漏洞；服务商、网络防护、补丁和监控仍由部署者负责。配置与验证步骤见[部署指南](../deployment/README.md)。

## 私有存储

SQLite 包含隐藏身份、任务牌、会话与签名密钥，必须放在静态目录外，限制文件与备份访问权限。数据库未实现全库加密；能读取服务账号文件的主机管理员属于信任边界。

服务使用单写者存储。异常写入会暂停游戏并使健康检查失败，不应通过删库恢复健康；备份、容量监控和灾难恢复需要部署方安排。不要直接扩成多个写入同一数据库的应用副本。

## 可选语音

LiveKit 令牌短期、限房间和成员，发布权限跟随游戏阶段；不授予摄像头、管理或录制权限。项目不保存录音，不启用 Egress。

WebRTC 提供传输加密，但本项目没有实现 E2EE；媒体服务器和获准收听的成员属于信任边界，也无法阻止参与者自行录音。公网媒体需要受信证书、正确的媒体端口和必要的 TURN，不能仅凭游戏页面可访问就判断语音可用。

## 公开文件

源码、测试、CI、部署模板和这份设计说明可以公开；真实配置、数据、日志、备份、工具会话、内部验收和未披露漏洞材料不能公开。`.env.example` 只能包含占位值。

内部维护记录不参与构建、运行或公共 CI。素材的公开许可与逐文件摘要另见[素材清单](../media/assets.json)，代码 MIT 不能代替第三方媒体的分发条件。

安全检查只覆盖当次测试与已知公告，不能证明不存在未知漏洞。上线前仍需在自己的 Linux、证书、防火墙、备份及真实终端环境验收。
